# Exordium 디자인 기준

기존 네오브루탈리즘과 6개 테마를 유지하는 역할별 기준이다. 색상은 `src/shared/constants/themes.ts`, 타이포그래피·레이아웃 역할은 `src/styles/typography.css`, 긴 글 본문은 `src/styles/content.css`에서 관리한다.

## 글자 위계

아래 px 값은 기본 글자 크기 16px 기준이다. 실제 스타일은 rem을 사용하며 브라우저 기본 글자 크기를 존중한다. 굵기·행간까지 역할의 일부로 본다.

| 역할 | 클래스 / 위치 | 모바일 / PC | 행간·굵기 | 적용 |
| --- | --- | --- | --- | --- |
| 브랜드 이름 | 기존 `text-display` | 40–96px 유동 | 0.9 / 900 | 홈의 이름만 사용하는 의도적인 예외 |
| 페이지 제목 | `type-page` | 36 / 48px | 1.1 / 900 | Posts·Projects·글 상세 |
| 섹션 제목 | `type-section` | 24 / 30px | 1.2 / 900 | Recent Posts·댓글 |
| 카드 제목 | `type-card-title` | 18px | 1.5 / 700 | 글·프로젝트 카드 |
| 본문·페이지 설명 | `type-body` | 16px | 1.625 / 기본 400 | 페이지 부제·글 설명·팝오버 제목 |
| 간결한 요약 | `type-summary` | 14px | 1.5 / 400 | 카드 요약·댓글 안내 |
| 보조 정보 | `type-meta`, `text-xs` | 12px | 약 1.333 | 날짜·태그·입력 도움말·보조 조작 |
| 구분 라벨 | `type-eyebrow` | 12px | 약 1.333 / 600 | About Me·Writing, mono·대문자 |
| 편집 화면 제목 | `form-heading` | 24px | 1.25 / 800 | 프로필·글 편집 |
| 폼 라벨 | `form-label` | 12px | 1.5 / 500 | 프로필·프로젝트·글 편집 |
| 폼 입력 | `Input`, `Textarea` | 16 / 14px | 기본 400 | 모바일 입력 확대 방지, PC 폼 밀도 |
| 긴 글 본문 | `.post-content` | 16–18px 유동 | 1.85 / 기본 400 | 실제 글 읽기 영역 |

본문 안의 h1/h2/h3은 각각 본문의 2/1.6/1.3배, 행간 1.3, 굵기 750이다. 문단 사이 1.25em, 제목 위 1.8em·아래 0.6em의 기존 읽기 리듬을 유지한다. 모바일 입력 글자는 16px, PC 폼 입력은 14px이다. 공통 동작 버튼은 12px mono, 탐색 링크는 기존 크기를 유지한다. 글 작성 본문은 폼 보조 입력과 구분하여 읽기 크기를 유지한다. 새 10px 라벨을 추가하지 않는다.

## 간격 위계

| 역할 | 기준 | 적용 |
| --- | --- | --- |
| 기본 단위 | 4px | Tailwind spacing 단위 사용 |
| 밀접한 아이콘·태그 | 4–8px | 칩 6px, 목록 속 칩 8px도 허용 |
| 같은 그룹 | 12–16px | 카드 그룹 간 12px, 제목→요약 8px |
| 카드 내부 | 20px (`--space-card`) | 글 카드와 로딩 카드 공유 |
| 카드 사이 | 16px | 1열·2열 목록 동일, 카드 최소 폭 18rem에 따라 자동 전환 |
| 페이지 좌우 | 24px (`--space-gutter`) | 헤더·홈·목록·상세·푸터 정렬 |
| 섹션 내부 | 모바일 32 / PC 64px | `section-space`, 홈·목록·페이지 헤더 |
| 편집 화면 내부 | 모바일 24 / PC 32px | 글 작성 제목과 입력 영역 |
| 읽기 영역 내부 | 모바일 32 / PC 48px | `reading-space`, 글 상세·푸터 |
| 제목→목록 | 모바일 24 / PC 32px | 홈 최근 글 |

페이지 역할의 PC 전환은 40rem이다. 글 목록은 `post-grid`가 카드 최소 폭 18rem을 기준으로 열을 결정한다. 기본 글자 크기에서는 640px부터 2열이고, 글자가 커지면 같은 화면 폭에서도 1열로 돌아간다. `page-shell`은 전체 폭 최대 64rem, `reading-shell`은 최대 48rem이며 좌우 여백을 포함한다. 헤더의 기본 높이 64px, 버튼의 최소 조작 영역 44px는 별도의 조작성 기준이다. 크게 확대한 글자 때문에 공간이 부족하면 헤더와 메뉴가 줄바꿈한다. 본문의 em 간격은 UI의 4px 배수에 강제로 맞추지 않는다.

## 글 카드와 태그

- 글 카드 높이는 15rem(기본 240px)으로 통일한다. 제목과 요약은 카드 상단에서 시작하며 각각 최대 2줄로 제한한다. 짧은 제목에 빈 두 번째 줄을 확보하지 않는다. 남은 공간은 본문 그룹 아래로 배분하고, 태그(조작 높이 44px)와 날짜(16px)는 하단에 배치한다. 태그가 없으면 해당 행을 생략하고 날짜 위치와 카드 높이는 유지한다. 로딩 카드도 같은 순서·높이·패딩을 사용한다.
- 제목과 요약의 원문은 데이터와 접근 가능한 텍스트에 보존하고 시각적으로 말줄임한다. 전체 글은 글 링크로 읽는다.
- `PostTags`는 태그 링크의 실제 조작 너비와 사용 가능한 가로폭을 측정한다. 한 줄에 들어가는 태그를 보여주고 넘는 개수는 `+N`으로 표시한다. 태그 하나가 너무 길면 말줄임과 더보기 아이콘을 사용한다. 화면을 넓혀 모든 태그가 보이면 팝오버를 닫고, 다시 좁혀도 자동으로 열지 않는다.
- 더보기는 글 링크와 별개인 44px 버튼이다. 전체 태그는 폭을 제한한 팝오버 안에서 줄바꿈하고, 내용이 길면 팝오버 내부를 스크롤한다. Escape·닫기 버튼·바깥 클릭으로 닫는다. 카드와 상세가 같은 컴포넌트를 사용한다.
- 카드의 제목 링크가 카드 전체 클릭 영역을 제공한다. 태그 링크·더보기 버튼은 형제 요소로 분리하며 조작 영역은 최소 44px이다. 태그 조작에 마우스를 올리면 해당 태그만 강조하고, 카드 본문에 올리면 제목·카드 경계·화살표와 primary 색상 4px 오프셋 그림자가 반응한다. 글 링크의 키보드 초점에도 같은 그림자를 표시한다. 그림자와 경계는 기존 200ms CSS transition으로 들어오고 나간다. 버튼 그림자도 색상과 함께 150ms 동안 전환한다.
- 카드·상세·팝오버의 태그는 `/posts?tag=…`로 연결한다. 목록은 선택 태그·필터 해제를 표시하고 정확히 해당 태그가 붙은 글만 조회한다. URL에 필터를 보관하므로 새로고침·뒤로 가기·주소 공유에도 조건이 유지된다. 결과가 없으면 태그 전용 빈 상태를 보여준다. 글 더보기에도 같은 필터를 적용한다.
- 태그 더보기와 글 더보기는 클라이언트 이벤트가 준비되기 전까지 비활성화한다. 일반 태그 링크는 서버 렌더링부터 실제 href를 제공한다.

## 색과 경계

기존 primary 면색을 사용하고 작은 강조 글자는 `primary-ink`, 홈의 큰 이름은 `primary-display`를 사용한다. 카드·팝오버에는 중립색 1px 경계를 사용한다. 태그 전체 보기 패널은 primary 헤더로 구분하며 그림자는 없다. 글자색인 foreground를 팝오버의 굵은 바깥선으로 사용하지 않는다. 문서 바깥 배경은 background로 통일하여 모달이 스크롤바 자리를 확보해도 테마색 띠가 드러나지 않게 한다. 글 카드는 글 영역 hover·키보드 초점에서만 primary 4px 그림자를, 게시·저장 버튼은 hover에서만 primary-ink 3px 그림자를 표시한다. 주요 버튼의 기본 경계도 primary-ink이며 상시 검은 그림자를 사용하지 않는다. 삭제 동작은 destructive 토큰을 사용한다. 태그 더보기에 새로운 색을 추가하지 않는다.

## 팝오버와 리액션

- 태그 전체 보기와 댓글 반응 추가는 `shared/ui/components/popover.tsx`를 공유한다. 등록된 `@basecn/popover`의 Base UI 구성을 사용하고, 전환은 해당 프리셋의 tw-animate-css만 사용한다. 별도 keyframes·JS 애니메이션은 추가하지 않는다. 모션 감소 설정은 열림·닫힘 상태보다 우선한다.
- 팝오버는 기존 popover 면색·글자색, 중립 1px 경계, radius-xs를 사용한다. 화면 가장자리 충돌 처리는 Base UI Positioner에 맡기고, 가용 높이를 넘는 내용은 내부에서 스크롤한다.
- 태그 전체 보기의 기본 폭은 18rem이다. 바깥 패널은 공용 Popover의 1px input 경계, 헤더는 primary 면색·primary-foreground와 16px 굵은 제목으로 구분한다. 헤더 아래에 별도의 굵은 구분선을 추가하지 않는다. 태그 목록은 기존 popover 면색에 16px 여백과 8px 간격을 사용한다. 닫기 버튼의 조작 영역은 44px를 유지한다.
- 팝오버의 태그도 카드와 같은 `.post-tag`를 재사용한다. 12px 모노·대문자·1px 경계·기존 색을 유지하며, 팝오버에서만 긴 태그의 줄바꿈을 허용한다. 팝오버 정돈을 이유로 태그를 별도의 산세리프·배경형 칩으로 바꾸지 않는다. 패널과 콘텐츠의 시각적 문제는 각각의 책임 범위에서 수정한다.
- 태그 팝오버는 더보기 버튼의 끝에 정렬하고, 화면 가장자리 충돌 시 Base UI가 위치를 보정한다. 팝오버 안의 태그를 선택하면 패널을 닫고 해당 글 목록으로 이동한다.
- 글 반응은 Base UI의 다중 선택 ToggleGroup이다. 이모지와 숫자를 가로로 배치하고 내용 너비에 맞춰 4px 간격으로 정렬한다. 보이는 칩은 28px 높이, 이모지는 14px이고 실제 버튼은 최소 44×44px이다. 기본 글자 크기에서는 320px 화면에도 다섯 반응이 한 줄에 들어가며, 글자 확대나 큰 카운트에서는 자연스럽게 줄바꿈한다. 숫자는 12px이며 0부터 표시하고 고정 폭 숫자와 최소 두 자리 공간을 사용한다.
- 기본 반응은 card 면색·border 경계·muted-foreground 숫자를 사용한다. 선택 상태는 primary-ink 경계와 옅은 accent 배경·foreground 숫자로 구분하며, hover 중에도 선택 경계를 유지한다. 기존 테마 토큰을 재사용하며 primary 전체 면색·이모지 확대·카운트 튀기기·별도 색상 애니메이션·상시 그림자는 사용하지 않는다. 비로그인 상태에도 카운트가 흐려지지 않도록 칩에 투명도를 적용하지 않는다.
- 글의 리액션 제목은 12px 모노 글자, 버튼과의 간격은 4px이다. 제목·반응 묶음·로그인 안내를 중앙 정렬한다. 본문과는 32px 위 여백·1px 구분선·24px 안쪽 여백으로 분리한다. 댓글 반응과 추가 버튼도 같은 작은 칩 표현과 44px 조작 영역을 쓴다. 추가 선택 팝오버는 내용 너비와 8px 패딩으로 구성하며 접근성 제목은 유지하되 시각적으로 숨긴다. 글과 같은 ReactionBar를 재사용한다.
- ReactionButton은 표시와 접근성, ReactionBar는 선택 연결, ReactionPopover는 팝오버 열기/닫기를 맡는다. 인증·저장·실패 복구는 feature/widget에 둔다. 저장 중에는 Base UI `focusableWhenDisabled`로 키보드 초점을 유지하면서 중복 입력을 막는다.

## 운영자 편집 화면

- 프로필 폼은 최대 48rem으로 제한하고 기본 정보·스킬·링크를 구분한다. 그룹 내부 12–20px, 그룹 사이 32px을 사용한다. 기본 정보는 PC에서 이미지와 텍스트를 나란히 배치하고 모바일에서는 쌓는다.
- 이미지 선택은 react-dropzone의 클릭·키보드·드래그 입력을 사용한다. 이미지 한 장, JPEG/PNG/WebP, 2MB 제한을 업로드 API와 공유한다. 업로드 중 중복 입력을 막고 기존 이미지 보존·재시도·저장·취소 시 임시 파일 정리 흐름을 유지한다.
- 스킬은 번호·이름·위/아래 이동·삭제가 있는 세로 목록이다. 순서는 화면과 키보드·드래그 모두 동일하다. `SkillOrderItem`은 개별 센서를, `SkillOrderField`는 순서 조정을 맡는다. 각 조작 영역은 최소 44px이다.
- 프로젝트 추가는 목록 보조 동작이므로 아이콘+outline 버튼을 사용한다. 저장은 기본 버튼이며 취소와 함께 오른쪽에 배치한다. 글 작성의 하단 동작도 같은 Button을 재사용한다.
- 검색 입력에는 별도의 내부 사각 outline을 만들지 않고 입력 행의 테마색 경계로 초점을 표현한다. 닫기 버튼 등 키보드 조작의 초점과 Escape 후 진입 버튼으로의 초점 반환은 유지한다.
- 버튼·링크·메뉴 등 조작 가능한 요소는 pointer, 텍스트 입력은 text, 드래그 손잡이는 grab, 비활성 조작은 not-allowed를 사용한다.

## 댓글과 작성 진입

- 댓글과 답글의 본문은 14px·행간 1.625이며 줄바꿈을 보존한다. 내용 내부 간격은 8px, 반응·답글·삭제는 같은 동작 행에서 4px 간격으로 배치한다. 좁은 화면에서는 동작 행과 작성자 정보가 줄바꿈한다.
- 답글·취소·삭제는 공용 Button의 ghost/sm을 사용한다. 글자는 12px, 조작 영역은 최소 44px이며 삭제만 hover에서 destructive 색을 사용한다.
- 댓글 입력의 placeholder는 14px, 실제 입력은 모바일 16px·PC 14px이다. 모바일 포커스 확대를 막으면서 안내 문구의 위계를 낮춘다. 도구 행은 4px 세로 패딩과 44px 동작 영역을 사용한다. 댓글 섹션은 32px 위 여백·24px 안쪽 여백·16px 그룹 간격을 사용한다.
- 고정 작성 버튼은 card 면색·primary-ink 글자와 경계를 사용해 primary 푸터와 구분한다. hover/키보드 초점의 4px 테마 그림자에 background 1px 경계를 더해 같은 색 배경에서도 구분한다. hover 시 1px 이동과 그림자가 150ms 동안 전환되며 모션 감소 시 이동을 생략한다. 개발 도구 진입점은 왼쪽 아래에 두어 작성 버튼을 가리지 않는다.

## 읽기와 페이지 전환

- 방향은 각진 본문 판이 자리에 놓이는 짧은 전환이다. 헤더·하단 메뉴를 정지시킨 채 본문만 아래 8px에서 240ms 동안 정렬하고, 이전 본문은 90ms 동안 사라진다. 튀는 탄성·전체 화면 색상 덮개·반복적인 섹션별 등장은 사용하지 않는다.
- TanStack Router의 기본 View Transition을 사용한다. 최초 문서 표시, 같은 경로의 검색/해시 변경, 편집 화면 진입·이탈에는 적용하지 않는다. 지원하지 않는 브라우저와 모션 감소 설정에서는 즉시 탐색한다. 경로 변경을 위해 Outlet을 강제로 재마운트하거나 편집 폼을 중복 렌더링하지 않는다.
- Lenis 1.3.26은 정밀 포인터가 있는 읽기 화면의 휠에만 적용하며 lerp는 0.18이다. 터치·키보드·중첩 스크롤은 기본 동작을 사용한다. 모션 감소·편집 중에는 인스턴스를 해제하며 설정 변경도 반영한다. Base UI는 브라우저에 따라 html 또는 body를 잠그므로 두 요소의 inline overflow에 맞춰 Lenis를 멈추고 재개한다. 검색 입력의 초기 초점은 preventScroll로 읽던 위치를 보존한다. 내부 스크롤은 allowNestedScroll과 prevent로 연결한다. 페이지 이동 전 관성을 끝내고 실제 위치 복원은 기존 라우터에 맡긴다.
- 스크롤 인스턴스 수명은 ReadingScroll, 전환 적용 조건은 createPageTransition, 효과는 navigation-motion.css가 맡는다. 기존 팝오버 애니메이션에는 별도 모션을 덧붙이지 않는다.
- API 기준: [Lenis 공식 문서](https://github.com/darkroomengineering/lenis), [TanStack Router 전환 옵션](https://tanstack.com/router/latest/docs/api/router/RouterOptionsType).

## 검증 기준

`e2e/comment-appearance.spec.ts`는 320/1440px에서 댓글 동작의 같은 글자·조작 크기, placeholder와 실제 입력의 구분, 답글 취소·삭제 취소 후 초점, 입력창 내부 스크롤을 검증한다. `write-action-appearance.spec.ts`는 6개 팔레트 × 밝은/어두운 상태에서 푸터와 버튼 면색 분리, hover 그림자·실제 클릭 대상·모션 감소·작성 진입을 확인한다. `navigation-motion.spec.ts`는 첫 클라이언트 탐색의 실제 중간 프레임, 휠 보간, 모달 배경 잠금, 뒤로 가기 위치 복원, 모션 감소와 미지원 API의 탐색 동작을 보호한다. 기대값은 현재 수용 기준이며 기존 CSS 클래스 문자열을 정답으로 삼지 않는다.

`e2e/post-card-layout.spec.ts`는 길이가 다른 콘텐츠, 태그 없음·다수·긴 단일 태그를 실제 로컬 DB에서 읽는다. 320/390/640/1440px에서 카드 높이·날짜 정렬, 두 줄 제한, 태그 열기/닫기·포커스 반환·글 이동을 검증한다. 200% 기본 글자 확대와 viewport 변경도 확인한다. CSS 클래스 문자열을 정답으로 검사하지 않는다.

`e2e/post-tag-navigation.spec.ts`는 태그의 정확한 일치(제목에만 등장하거나 접두어만 같은 글 제외), 특수문자 URL, 새로고침·뒤로 가기·필터 해제, 모바일 팝오버에서 목록 이동, 빈 결과와 페이지 추가 조회를 검증한다. 실제 로컬 Supabase를 사용하고 테스트에서 만든 글만 정리한다. 레이아웃과 탐색 동작의 테스트 파일은 분리한다.

타이포그래피·간격 변경은 같은 역할의 실제 계산 스타일과 화면으로 판단한다. 브라우저 화면 배율, 모바일 운영체제 글자 확대, 실제 휴대폰·Safari 검증과 Chromium의 rem 확대 검증은 별개이다.

`e2e/reaction-controls.spec.ts`는 320/1440px에서 크기 유지, 다중 반응 선택·취소, 느린 저장 중 초점·중복 입력 차단, 실제 로컬 DB와 새로고침 후 상태, 댓글 팝오버의 닫기와 초점 반환을 확인한다. 모션 감소 설정은 `post-card-layout.spec.ts`에서 실제 계산된 애니메이션과 콘텐츠·닫기 동작으로 검증한다.

`e2e/reaction-appearance.spec.ts`는 작은 시각적 크기와 44px 조작 영역을 각각 측정하고, 칩 바깥의 버튼 여백을 눌러도 저장되는지 확인한다. 6개 팔레트의 밝은/어두운 상태에서 선택 경계의 테마 일치, 숫자 대비, 200% 기본 글자 확대 시 가로 넘침을 검사한다. 시각적 수용 조건과 저장/키보드 동작은 서로 다른 테스트 파일에서 관리한다.

`e2e/interaction-feedback.spec.ts`는 카드 hover 대상 분리·검색 초점·모달 스크롤바 여백의 배경 일치를 확인한다. `e2e/operator-appearance.spec.ts`는 320/1440px 폼 글자 위계·세로 스킬 목록·커서·44px 조작 영역·버튼의 hover 전후 그림자를 실제 계산 스타일과 캡처로 확인하고 6개 팔레트 × 밝은/어두운 상태의 버튼 대비도 검증한다. `avatar-field.test.tsx`는 드롭과 동시 입력·다중 파일 거절, 기존 프로필 테스트는 형식/크기·실패 재시도·저장/취소를 보호한다. 실제 업로드 바이트와 임시 파일 정리는 `project-profile.spec.ts`에서 로컬 Supabase로 검증한다.
